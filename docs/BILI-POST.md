# B站动态：发布稿（可直接复制）

> 2026-10-26 · 配图：`docs/bili-post-card.png`（1200×630）
> 这条动态的作用是把两个仓连起来：**jellyfish（数字生命）** 与 **bili-daily-ops（日更运营）**。

## 动态正文（约 190 字，直接粘贴）

```text
写了个很小的东西：一只会死的水母。

它每天只有两个选择——吃，还是走。体力归零就饿死。我养的第 1 只活了 17 天，
死因写在一行日志里：「第 17 天饿死，它吃了 5 次，走了 7 次」。

有意思的不是它会死，是它的一生可以被倒回去重看：每一 tick 都写进一条
带哈希链的日志，状态完全由日志算出来。所以同一份日志，在谁的机器上重放，
都会得到一模一样的那只水母（改一个字节立刻报错）。

给它换个种子，就是另一只；给它换一行决策函数，就是另一种活法。
单文件、零依赖、不用任何 key。

仓库：github.com/hansei996/jellyfish
（顺手把日更那套准入卡/断更判定也接上了——它管的是「别断更」，这个管的是「别忘」）
```

## 评论区第一条（自己补，放细节）

```text
玩法：
1) 不用装：curl -s <raw地址> | python - tick --times 30
2) 看它活着：python jellyfish.py serve
3) 换一只：--name 你的名字 --policy frugal / adventurous / opportunist
四种性格实测中位寿命：balanced 12 天 / frugal 13 天 / adventurous 4 天 / opportunist 22 天。
全部会死（扫了 60 个种子，没有一个永生）。
```

## 图像选择

用的是**死掉那一张**（`bili-post-card.png`）：画面变灰、伞盖缩小、体力曲线归零。
理由：动态的打开率取决于「这是一个什么画面」。活着的蓝色水母和普通插画没区别；
**灰色的、刚死的那只**才有信息量。

## 这条动态不做什么

- 不喊「AI 数字生命革命」——它只是一个 848 行的单文件
- 不承诺播放量、不蹭热点
- 不说「它会不会自己乱来」这类恐怖叙事（它没有行动力）

## 和日更那个仓的闭环在哪

| 仓 | 管什么 | 一句话 |
|---|---|---|
| `bili-daily-ops` | 别断更 | 选题准入卡 + 库存水位 + 断更判定（`gaps:3`） |
| `jellyfish` | 别忘 | 每一次决策都留痕，一生可重放 |

两者的共同点：**都不靠手感，都靠可复算的规则。**
